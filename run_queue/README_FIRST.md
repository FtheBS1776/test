# Bounded active-host task queue — NONCLAIM

Read PLAN_AND_CORRESPONDENCE.md. This extends the existing bridge/journal with scheduling decisions and reserved-call limits. It does not invoke a model, replace inherited authority or create a background service. Python3.12 standard library; sibling host_adapter/worker_bridge modules reused and pinned.

`run_policy.py DATABASE init` reads exact policy JSON: run_id, max_tasks/max_model_calls (integers1–8), effect_scope=owned-local-report-inbox. Own a freshly provisioned file; no implicit old-ledger migration. `enqueue` reads an immutable bridge plan. `next` selects one READY task, resumes ACTIVE work first, skips scoped HOLDs, and records STOP reason when no authorized work can start. `reserve` reads {run_id,request}, with the exact bridge request; only new RESERVE_ONCE is a new charged slot. Replayed request returns RECONCILE_RESERVATION, never launch permission. Reservation identity is the pair (run_id,slot_id); an exported slot alone is not globally unique. UNKNOWN invocation still consumes the slot. Repair attempts consume another slot. Limits count reserved model attempts, not dollars/tokens or guaranteed executions.

Host order: select task -> provision its bridge/journal/sink -> bridge.request -> queue.reserve -> journal.begin -> controller collaboration tool -> journal.observe -> candidate/review/delivery -> queue.complete. Queue and per-task ledger are separate stores; no global atomicity claim. A gap after reservation needs explicit reconciliation with existing host call history/journal. Neither missing agent nor unused-looking reservation is permission to silently relaunch or refund. The trusted host could bypass these helpers; no hostile-worker confinement claim.

`complete` reads {run_id,task_ledger,sink}; it binds the exact full reserved request, accepted task/effect and fresh existing destination. Worker DONE, accepted text or cached COMPLETE cannot substitute for current sink readback. Queue COMPLETE records a historical verified event. `status` shows that scope; re-observe destination before relying on currentness. `hold` isolates a task; independent READY tasks can continue within remaining budget. `stop` preserves an explicit host/authority/dependency boundary. Exhausted/stopped runs do not authorize new calls; existing work may still be reconciled/read back. STOPPED active work returns RECONCILE_TASK with allow_new_invocation=false; host must not turn that into a fresh launch. `inspect` returns UNKNOWN and preserves incomplete/unreadable queue files; it does not overwrite or migrate them.

Exact paths added/removed/changed/unchanged aid inspection; they do not establish semantic progress or truth. Comparison reuses the reviewed verifier and immutable bounded snapshots anchored to expected outer hashes. No archive extraction or execution. Source-pin checks concern owned-source integrity, not hostile check/use isolation.
