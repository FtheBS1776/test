# Source research and cross-check disposition

Current primary sources retrieved on 2026-10-06: Linux signal(7) and wait(2) manuals; Python3.12 monotonic clock/socket timeout documentation; etcd3.6 failure modes/API guarantees; five exact official source files at a0614505aff9b8ff469e9c59c2d979a5936d13f4 independently SHA-256/Git-blob bound in SOURCE_RETRIEVAL_INDEX.json.

Linux SIGSTOP stops a process and WUNTRACED/WIFSTOPPED can observe child stop status. These are process observations, not application flush or filesystem transaction guarantees. Python's monotonic_ns is suitable for declared same-host intervals. Socket timeout settings do not establish a whole-operation deadline; the network stack can return a timeout independently. Therefore an adapter-call end stamp or predicted configured deadline is insufficient to timestamp the actual observed transport exception. A candidate must explicitly declare any delegating diagnostic wrapper needed to stamp the real Gateway exception, without substituting authority or changing the actual request/error. No such instrumentation is implemented in this batch.

Exact raft.go sends leader messages before local storage.Save. Exact wal encoder buffers records; wal.sync flushes the encoder and invokes fdatasync. A process pause can therefore miss bytes still in user buffers or interrupt a write. Stop detection, byte stability, decoded positive target and strict terminal integrity have different roles. No pause itself establishes durability or majority commit. Current etcd failure-mode guidance permits an old leader's uncommitted entries to be overwritten, so neither later late commit nor later discard is assumed.

Critical counterexample: exact wal.ReadAll read-only mode accepts io.ErrUnexpectedEOF and clears it, losing terminal decoder condition. The copied-artifact test in evidence/torn_tail_counterexample retains the complete entry7/commit7 history, appends a partial declared-length frame, and the original observer returns zero while the old bounded history validator passes. This does not invalidate the positive target history in the original authentic capture. It defeats transferring its high-level success code into a complete live-tail claim. No production vulnerability, exploitability, recovery behavior or provider defect is inferred.
