# Persisted model-worker bridge — bounded NONCLAIM prototype

Read CORRESPONDENCE_AND_PLAN.md first. This adds local host workflow bookkeeping around the existing collaboration worker interface; no model API credentials, daemon or authority-adapter replacement. Python emits host actions; the Work controller performs the supported worker call and persists its binding. It cannot directly invoke the collaboration API from a subprocess.

Use Python3.12 with the standard SQLite module. Reused report_sink.py and stateful_subject.py are unchanged files from report R2 source8a676ca5dddbbaff3d4e286ee3f256605a7341b6. Only report sink operations and EID hashing are called. Their SHA256 values are pinned in bridge.py and checked before imports; changing a dependency rejects startup. No provider runs or cryptography installation needed for this unit. Run `python3.12 -B worker_bridge/test_bridge.py` for targeted local checks.

## Host protocol

1. Provision a new owned ledger with `python3.12 -B worker_bridge/bridge.py /absolute/path/tasks.sqlite init`; provision destination separately using reviewed `report_sink.initialize`. If provisioning is interrupted, `inspect` reports UNKNOWN for missing/incomplete/unreadable schema and preserves the file. Schema creation is one transaction; the initial exclusive file reservation can still be interrupted. Inspect and retain that file, then use a separately named fresh ledger only after host reconciliation; no automatic replacement.
2. `create` reads exact JSON plan from stdin: task_id, goal, input_sha256 (canonical manifest digest), max_attempts (1–4).
3. `request` commits the request before returning DISPATCH_ONCE. Only that initial action permits the host worker call. Repeated request/status returns RECONCILE_WORKER. If agent binding is missing, dispatch is uncertain; reconcile actual host history, never invent a binding or start a duplicate blindly.
4. `bind` reads `{n,agent,task_id,input_sha256}`. Root chooses the owned database explicitly. `submit` reads `{n,agent,text,task_id,input_sha256}`. Controller verifies worker input/candidate hashes against pinned bytes before ingest. The bridge checks task/input/attempt/agent and preserves exact candidate bytes; duplicate mismatches fail.
5. `review` reads `{n,candidate_hash,decision,reason,task_id,input_sha256}`; decision ACCEPT or REPAIR, reason bounded nonempty string. Only the trusted controller should invoke it after concrete review. This is not authenticated independent reviewer identity. REPAIR makes the next request carry feedback. Attempts bounded; exhausted repairs HOLD.
6. `deliver --sink /absolute/path/report_inbox.sqlite` accepts only a candidate with exact accepted review. It uses the unchanged local sink effect ID and full-payload duplicate check. Completion requires fresh destination observation. `status --sink ...` rereads destination even after ledger says DELIVERED. Missing destination -> UNKNOWN; it is never recreated by delivery.

The actual trial reviews the original pinned bridge source; root found and repaired a missing explicit task/input response binding before publishing revised code. Worker findings also led to pinned reused dependencies and a nonoverwriting incomplete-provision inspection path. The worker's memo is evidence about the original subject, not approval of repaired code. Preserve this distinction. Source-v1 snapshots are review-only historical inputs, not runnable packages.

Tests exercise uncertain dispatch, cross-task/wrong-input candidate/review, stale versions, duplicate different bytes, concurrency, unaccepted delivery, lost acknowledgement and fresh-process retry, missing destination, damaged review and attempt cap. No earlier provider fixture is rerun. Single trusted host/owned local filesystem; same-agent roles and ledger checks do not prove hostile isolation, rollback resistance, power-loss durability, remote authenticity or arbitrary text truth. No always-on operation after host ends.
