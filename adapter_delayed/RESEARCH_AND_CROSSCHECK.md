ThreadingMixIn close waits for non-daemon workers; shutdown must run from a different thread than serve_forever. The fixture uses one owned loopback listener, bounded body/socket/upstream/hold waits, selected routes/namespace, finite request cap, explicit worker count and cleanup, releasing any held request before shutdown. It is not a production server or generic forwarding proxy.

Cross-check: fixed upstream assigned by owned-cluster constructor; no CLI endpoint. One fixed adapter binding endpoint. One actual timeout plus absent receipt is UNKNOWN, never NOT_COMMITTED. Identical retry may legitimately win while original remains pending; original then loses Compare with no second update. Scope is before-upstream transport delay, not already-in-Raft or production administration.
