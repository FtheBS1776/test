# Checkpoint ZIP integrity CLI — bounded contract

Implement Python3.12 standard-library-only `verify_checkpoint.py`. CLI: positional ZIP path and mandatory `--expected-sha256` (exact64 lowercase hex). Read-only, no archive extraction, archive-code import/execution, network or source changes. Expected hash compares bytes with caller supplied anchor; passing hash/manifest is integrity/binding, not independent authenticity, claim validity or semantic replay.

Supported Genie transport has only regular files and a root MANIFEST.json. JSON manifest maps each nonmanifest ZIP member path to exact object {sha256:64 lowercase hex,size:nonnegative exact int}; no bool sizes; reject duplicate JSON keys. Require exact member inventory excluding manifest and compare each actual uncompressed SHA256/size; root manifest itself not listed. Repeated manifest/member names reject. Reject absolute names, backslashes, empty or '.'/'..' path components, Windows drive prefixes, symlink entries and directory entries. Enforce before decompressing: <=4096 members, <=64MiB total declared uncompressed sizes, <=24MiB per member, <=1MiB manifest; stream member hashing and enforce actual per-member/total bytes too. Handle malformed ZIP, CRC failures, missing manifest, bad expected hash/outer mismatch, unsupported schema and I/O errors with clean JSON rejection and nonzero exit. Successful JSON includes status PASS, outer_sha256, payload_files, total_uncompressed_bytes, evidence_scope INTEGRITY_ONLY. No unconditional PASS after exceptions, no exception tracebacks in ordinary rejection output. A self-contained manifest is not independent trust.

Worker must inspect only contract and journal source; no root test inputs or ledger mutations. Worker writes code/status and a separate source review memo for journal; root handles acceptance/effects. Code payload should stay below12000 UTF8 bytes for the inherited bounded sink.
