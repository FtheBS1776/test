# Host invocation journal and checkpoint utility — NONCLAIM

Start with PLAN_AND_CORRESPONDENCE.md. Journal adds explicit host observations to a new owned bridge ledger. It imports the pinned existing worker_bridge/bridge.py and unchanged sink/EID modules. No schema migration of old evidence ledgers and no implicit provisioning. Python3.12 standard library only.

Provision the ordinary ledger, then `python3.12 -B host_adapter/journal.py /absolute/path/tasks.sqlite provision` before task creation. Existing bridge creates task/request. `begin` reads JSON `{n,task_id,input_sha256}` and commits one call identity per attempt before returning INVOKE_ONCE. Host invokes the collaboration tool only on that new action. Repeated begin returns RECONCILE_HOST even if no observation/agent exists; STARTED is not launch proof.

`observe` reads `{n,task_id,input_sha256,call_id,outcome,agent,evidence}`. Outcome UNKNOWN requires agent:null and never permits redispatch. OBSERVED_ACCEPTED includes exact host-observed agent and bounded nonempty evidence object; journal commits evidence and agent binding atomically. These records are trusted controller assertions, not signed provider receipts or independent evidence. An observed agent cannot be replaced/downgraded by later messages; new stale task/attempt/input/call observations reject. Exact duplicate event bytes are idempotent even after workflow progress; duplicate acknowledgement is not current outcome. `status` validates stored hashes/call/request/agent consistency and returns UNKNOWN with a preserve-and-inspect action on inconsistency. It shows host outcome and observation count. Worker completion and final effect completion remain separate: existing bridge verifies candidate/review; sink readback establishes local destination application.

Crash before host reply persistence requires actual host history/output reconciliation. No automatic assumption that a call never happened. A trusted controller could bypass this adapter or forge observations; hostile-worker isolation, rollback resistance, power-loss recovery and production trust remain scoped HOLDs. No model caller/background daemon embedded; collaboration interface available only in running Work host.

Useful task implements read-only `verify_checkpoint.py`, reviewed against UTILITY_CONTRACT.md. It checks a caller-pinned outer SHA256, strict ZIP paths/inventory/CRC/quotas and exact manifest payload hashes/sizes. It never extracts or executes archive contents. Passing is INTEGRITY_ONLY, not semantic validity/authenticity. Final source and actual trial outcome will be recorded separately; original rejected candidates remain evidence.

Targeted journal checks: `python3.12 -B host_adapter/test_journal.py`. Utility CLI: `python3.12 -B host_adapter/verify_checkpoint.py /absolute/path/checkpoint.zip --expected-sha256 <trusted-exact-hash>`. Review source and anchor before execution. No new paid provider or deployment.
