CROSS-ATTACK REPAIR PRESERVED
The first implementation/test run (workflow 38172996815, job 114569366426) passed 10/10 provisioner tests but did not include a direct mutant for post-move verification failure. Internal cross-attack found that after MoveFileExW reported success, a failure while re-opening/revalidating the final directory could escape as generic PROVISION_NAMESPACE_INVALID. That understated the authority boundary because publication might already be committed.

Repair commit 06897c27d4cf514acdbc883c7e074cdb290d1d76 moved every post-move verification operation under a committed-but-unverified boundary. Any such failure now becomes PUBLISHED_UNVERIFIED_PRESERVE. The final tested head 250e9c237ef0fe1c9cfade8cccb900e05a0c7e38 added the explicit mutant and passed 11/11.
